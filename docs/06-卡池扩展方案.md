## 1. 引擎能力边界

判断一张卡能不能做，看它需要的能力落在哪一级。分级标准是「要动多少引擎代码」，
不是「效果强不强」。

### 1.1 A 级：现有框架直接支持

写一张这样的卡，只需要在卡类里填 `BuildParam()` / `PlayEffect()`，不用改任何框架代码。

| 能力 | 引擎接口 |
| --- | --- |
| 伤害（单体 / 全体 / 随机 / 多段） | `DamageCmd.Attack(...).Targeting()/.TargetingAllOpponents()/.TargetingRandomOpponents()/.WithHitCount(n)` |
| 格挡 | `CreatureCmd.GainBlock(creature, amount, props, cardPlay)` |
| 抽牌 | `CardPileCmd.Draw(ctx, n, player)` |
| 回血 / 治疗 | `CreatureCmd.Heal(creature, n)` |
| 能量增减 | `PlayerCmd.GainEnergy / LoseEnergy / SetEnergy` |
| 星星增减（本体的第二资源） | `PlayerCmd.GainStars / LoseStars / SetStars` |
| 施加负面状态 | `PowerCmd.Apply<VulnerablePower / WeakPower / FrailPower / PoisonPower / ...>` |
| 施加增益状态 | `PowerCmd.Apply<StrengthPower / DexterityPower / PlatingPower / ThornsPower / IntangiblePower / RegenPower / ...>` |
| 加 / 减关键词 | `CardCmd.ApplyKeyword / RemoveKeyword`、`CardModel.AddKeyword` |
| 单回合保留 / 诡计 | `CardCmd.ApplySingleTurnRetain`、`ApplySingleTurnSly` |
| 生成牌入手 | `combatState.CreateCard<T>(player)` + `CardPileCmd.AddGeneratedCardToCombat` |
| 弃牌 | `CardCmd.Discard(ctx, card)`、`CardSelectCmd.FromHandForDiscard` |
| 消耗 | `CardCmd.Exhaust(ctx, card)` |
| 升级 / 降级 | `CardCmd.Upgrade / Downgrade` |
| 变形 | `CardCmd.TransformTo<T> / TransformToRandom` |
| 附魔 / 苦难 | `CardCmd.Enchant<T> / Afflict<T>` |
| 自动打出 | `CardCmd.AutoPlay(ctx, card, target)`、`CardPileCmd.AutoPlayFromDrawPile` |
| 洗牌 | `CardPileCmd.Shuffle(ctx, player)` |
| 塞诅咒 | `CardPileCmd.AddCurseToDeck<T>(player)` |
| 选一张手牌（升级 / 弃 / 消耗） | `CardSelectCmd.FromHand / FromHandForDiscard / FromHandForUpgrade` |
| 选一张战斗中的牌 | `CardSelectCmd.FromCombatPile` |
| 传参池读写 | `AlphaCorePower.AddParam / ConsumeParams / PeekParams` |
| 协议层读写 | `ProtocolPower.AddProtocol / ConsumeProtocol` |
| 迭代成长 | `IterationEvery` / `IterationStacks` / `IterationVarBonus` |

结论：**只要效果是「打出时发生一次的事」，基本都在 A 级**。包括需要玩家选牌的卡，
因为本体的 `CardSelectCmd` 已经把这套交互做好了。

### 1.2 B 级：需要小幅扩展框架

改动量小（每项约 10～30 行），但必须先改框架，卡才能写。

| 需求 | 要改什么 |
| --- | --- |
| 传参能给能量 / 星星 / 弃牌 / 上增益 | 扩 `ParamKind` 枚举 + `Describe()` + `AlphaCard.ApplyParam()` 各加一个分支 |
| 更多负面状态（绞杀 / 灾厄 / 虚弱变体等） | 扩 `DebuffKind` + `DebuffName()`。本体 Power 池里有大量现成的可挑 |
| 一张牌挂多条传参 | `BuildParam()` 从返回单条改成返回集合（`IEnumerable<ParamEntry>`） |
| 响应只消费池里「某一类」传参 | `ConsumeParams()` 加一个筛选谓词，池里其余的留着 |
| 迭代效果不是数值（如叠易伤层数） | 卡自己在 `PlayEffect` 里按 `IterationStacks` 算；卡面显示再配一个动态变量 + `IterationVarBonus` |
| X 费牌 | override `HasEnergyCostX`（本体已支持 X 费结算） |
| 星费牌 | override `CanonicalStarCost` / `HasStarCostX` |
| 本回合内「每打出一张牌就触发一次」 | 写一个临时 `CustomPowerModel`，挂 `AfterCardPlayed` 之类的钩子 |

### 1.3 C 级：需要新机制，成本中等

不是不能做，是投入产出比要单独评估。建议先不做。

| 需求 | 难在哪 |
| --- | --- |
| 传参池跨战斗保留 | 状态要从战斗内挪到 `RunState`，还要处理存档与显示 |
| 给「下一张打出的牌」打标记 | 要新增一套标记集合，并在 `OnPlay` 里判断与清除，边界情况多 |
| 改变弃牌 / 抽牌规则（如回合结束不弃手牌） | 要接本体的回合结束流程 |
| 临时改变卡牌费用 | 本体有 `TemporaryCardCost`，能用，但时机的坑较多 |
| 第二资源条（星星）的 HUD 显示 | 需要确认角色 HUD 是否支持，可能要改界面 |

### 1.4 D 级：不建议做

| 需求 | 原因 |
| --- | --- |
| 新的 HUD 元素（专属进度条 / 第二条能量） | 要改界面布局与美术，工作量远超卡牌本身 |
| 结算过程中让玩家做多步选择 | 本体的选择交互是「一次选完」，中途插入自定义选择流程要重做状态机 |
| 跨 run 的永久成长（存档级） | 涉及存档结构与平衡，且与 roguelike 的单局节奏冲突 |
| 改变出牌流程 / 回合结构 | 影响面太大，容易和其它 mod 冲突 |

## 2. 判断一张卡能不能做：四个问题

拿到任何一张设计，按顺序问：

1. **它的效果是不是「打出时发生一次的事」？** 是 → 基本 A 级。
2. **它要不要玩家在结算中途做选择？** 要 → C 级，先放一放。
3. **它的数值有没有现成的动态变量可以挂？** 有（伤害 / 格挡）→ 迭代和增幅都能直接吃；没有 → 要自己补变量。
4. **它要不要跨回合 / 跨战斗记住状态？** 要 → 看 1.3，多半是 C 级。

按这四条筛，「想当然」的效果大部分会落到 A / B 级，少数落到 C 级。

## 3. 三大机制的关系

先把循环画清楚，卡池才不是一堆孤立的效果。

```
   协议来源牌 ──写层数──> 协议层数
                              │ 回合开始消费
                              ▼
                        协议牌（α/β/γ）
                              │ 打出
                              ▼
   传参来源牌 ──────────> 传参池 ──响应牌消费──> 效果落在响应牌本次结算
                                                      │
                                                      ▼
                                                  迭代计数 +1
                                                      │
                                                      ▼
                                            本场战斗内这张牌永久变强
```

三条联动线：

- **协议 → 传参**：协议牌本身就是传参源，所以攒协议等于攒传参。
- **传参 → 迭代**：迭代牌如果同时是响应牌，就能一边吃池一边成长。
- **迭代 → 协议**：迭代效果里写「获得协议层数」，就能把滚雪球转成下一档协议牌。

## 4. 卡池提案

目标：普通 8 张、罕见 8 张、稀有 6 张，另加 3 张不依赖核心机制的骨架牌。
数值先不管，只定效果与可行性。

### 4.1 普通

| 卡 | 费 | 类型 | 效果 | 级别 |
| --- | --- | --- | --- | --- |
| 冷启动 | 0 | 技能 | 传参：抽 1 张牌。消耗 | A |
| 强制中断 | 1 | 攻击 | 造成 9 点伤害。响应 | A |
| 防御性应答 | 1 | 技能 | 获得 8 点格挡。响应 | A |
| 过载脉冲 | 1 | 攻击 | 造成 4 点伤害。传参：响应牌伤害与格挡 +50% | A |
| 指令队列 | 1 | 技能 | 传参：生成一张 α协议加入手牌 | A |
| 渐进强化 | 1 | 技能 | 获得 4 点格挡。迭代2：格挡 +2 | A |
| 协议缓存 | 1 | 技能 | 获得 2 层协议。抽 1 张牌 | A |
| 预热 | 0 | 技能 | 抽 1 张牌。传参：本牌获得「消耗」 | A |

### 4.2 罕见

| 卡 | 费 | 类型 | 效果 | 级别 |
| --- | --- | --- | --- | --- |
| 清算 | 2 | 攻击 | 造成「传参池条数 ×4」点伤害。响应 | A |
| 读取溢出 | 1 | 技能 | 抽「传参池条数」张牌。响应 | A |
| 协议回响 | 2 | 攻击 | 造成 6 点伤害 2 次。响应。传参：获得 2 层协议 | A |
| 累积运算 | 2 | 攻击 | 造成 8 点伤害。迭代2：伤害 +3 | A |
| 逆向工程 | 1 | 技能 | 弃 1 张手牌，抽 2 张牌。传参：抽 1 张牌 | A |
| 缓存写入 | 1 | 技能 | 传参：抽 1 张牌；传参：回复 3 点生命 | B |
| 反射装甲 | 1 | 技能 | 获得 5 点格挡。传参：获得 3 点荆棘 | B |
| 广播协议 | 2 | 技能 | 获得 4 层协议。本回合内每打出 1 张牌，再获得 1 层协议 | B |

### 4.3 稀有

| 卡 | 费 | 类型 | 效果 | 级别 |
| --- | --- | --- | --- | --- |
| 全量响应 | 3 | 攻击 | 造成 5 点伤害，重复「传参池条数」次。响应。消耗 | A |
| 溢出伤害 | 3 | 攻击 | 造成 12 点伤害。迭代1：伤害 +2。消耗 | A |
| 协议核爆 | 2 | 技能 | 消耗全部协议层数，每层对所有敌人造成 2 点伤害 | A |
| 递归调用 | 2 | 技能 | 传参：本牌重放 2 次 | A |
| 持久缓存 | 1 | 能力 | 回合开始时获得 1 层协议 | A |
| 终极迭代 | 2 | 技能 | 本场战斗中，本牌迭代间隔 −1（最低 1）。消耗 | C |

### 4.4 骨架牌（不依赖核心机制）

补这几张是为了让战斗奖励里出现「不需要配合也能用」的选项，避免每张牌都在等池子。

| 卡 | 费 | 类型 | 效果 | 级别 |
| --- | --- | --- | --- | --- |
| 横扫 | 1 | 攻击 | 对所有敌人造成 7 点伤害 | A |
| 铁壁 | 2 | 技能 | 获得 14 点格挡 | A |
| 过载运行 | 1 | 能力 | 每回合开始时获得 1 点能量，自身受到 2 点伤害 | A |

## 5. 落地建议

**第一批（纯 A 级）**：4.1 全部 + 4.2 的清算 / 读取溢出 / 协议回响 / 累积运算 / 逆向工程 + 4.3 前五张 + 4.4 全部。
这一批不动框架，写完就能编译测试，也刚好把「协议 → 传参 → 响应 → 迭代」四条线都填上。

**第二批（要动框架）**：先做「一条牌挂多条传参」和「扩 `ParamKind` / `DebuffKind`」两项扩展，
之后 4.2 的三张 B 级牌和后续所有需要新传参类型的卡都能直接写。

**暂缓**：`终极迭代`（C 级）。它需要把「迭代间隔」从卡上的固定值改成可被外部修改，
收益只有一张牌，等迭代机制在实测里站稳了再评估。
