## 1. 三大机制（定稿）

### 1.1 传参 / 响应

**传参**：带「传参」的牌打出时，向**传参池**里加入一条传参条目（效果见 §3）。

**响应**：带「响应」的牌打出时，**消费整池**，把池中每条传参的效果**全部作用在这张牌本次结算上**。

规则细节（已锁定）：

| 规则 | 内容 |
| --- | --- |
| 门禁 | **软门禁**：池空时响应牌**也能打出**，只是吃不到传参加成（不再卡手）。池非空时消费整池 |
| 结算顺序 | **先响应（消费池）→ 再本牌效果 → 再传参（重新入池）→ 最后迭代计数** |
| 效果作用域 | **一次性**：只作用于本次打出，不留在牌上 |
| 多条目 | 池中多条传参**同时**全部结算，效果叠加 |
| 特殊牌 | 「完全响应」可把吃到的传参**保留在牌上**（本场战斗内每次打出都重放）；「继承迭代」**不消费**池（只读不取） |

> **为什么结算顺序是「先响应再传参」**：这样一张同时带两者的牌会**自续**——
> 打出时先吃掉池里的旧传参，再把自己的传参放回去，池永远非空。
> 但**起始牌组现在没有这种牌了**（阿尔法突袭已去掉传参），点火只能靠「参数激活」。

**点火牌**：起始牌组必须有一张**不带响应、只提供传参**的牌，否则第一回合无牌可打。
现在就是「参数激活」。

### 1.2 协议

一个**层数计数器**（不是传参池，是独立资源）。

- **回合开始时**：消费**全部**协议层数 → 按档位往手牌加入**一张**协议牌。

| 消费的层数 | 获得的协议牌 |
| --- | --- |
| 0 | 无 |
| 1 – 4 | α协议 |
| 5 – 12 | β协议 |
| 13 + | γ协议 |

- 超过 13 层的部分（`层数 − 13`）结算时转等量**活力**，攒过头也不算白攒。

- 层数在回合开始时**清零**，所以「攒到高档位」必须在**同一个回合内**完成。
- 层数由「协议来源牌」写入（§4.3）。
- 协议牌自身都带 **消耗** + **虚无**（当回合不用就烂在手里）。

### 1.3 迭代

写法：**迭代X：效果**

- **这张牌每打出 X 次**，就把「效果」在**本牌上叠加一次**，效果**可累积**。
- **作用范围：本场战斗**，战斗结束随卡牌实例一起重置。
- **从下一次打出起生效**（本次打出的第 1 次不享受，第 2 次开始享受）。
- 实现上是一张牌一个「已打出次数」计数器，层数 = `次数 ÷ X`，结算时读取
  （不是 `BaseReplayCount`，那个是「重放」）。

**语义细节（重要）**：

- 效果叠加在**牌自身**，而不是「多打一次」。所以「造成 3 点伤害两次，迭代1：伤害+1」
  是 **(3+1)×2 = 8**，不是 3×2+1 = 7。
- 附加效果同样按「层数」叠，而不是按「次数」。例：「对所有敌人造成 8 伤害，迭代2：给予 1 层易伤」
  → 每打 2 次叠 1 层易伤；再完成一轮变成 **2 层易伤**（不是「1 层易伤触发两次」）。
  作用目标跟随**卡牌自身的指向**（单体 → 单体，全体 → 全体）。

| 牌 | 迭代 | 含义 |
| --- | --- | --- |
| 阿尔法突袭 | 迭代1：本牌伤害+1 | 第 1 次打 2 伤；第 2 次 3 伤，第 3 次 4 伤…… |
| 继承迭代 | 迭代1：格挡+1 | 第 1 次得 5 格挡，第 2 次 6，第 3 次 7…… |

**卡面表现（v0.5）**：

- 迭代牌卡面显示计数器：`迭代1（已打出 N 次）`，N 一直显示（含 0 次）。
- 迭代成长后的数值**实时反映在卡面数字上**：伤害 / 格挡走 `AlphaDamageVar` / `AlphaBlockVar`
  （原始值 = 基础值 + 迭代成长，再乘增幅，最后过引擎的 `Hook.ModifyDamage` / `ModifyBlock`，与实战同一条路径）；
  其它自定义迭代变量（如协议层数）由 `AlphaPreviewPatch` 补到 `PreviewValue`（见 §6）。
  所以第 2 次抽到这张牌时，卡面已经是 `3` 而不是 `2`。

> γ协议的传参给的是**重放 1**（`BaseReplayCount`），这是「本牌重放」，和「迭代」是两回事，
> 别混用词。

## 2. 状态显示与卡面词条

实测反馈「看不见池子 / 层数 / 词条 / 计数」，v0.3 已补齐，v0.4 又按反馈做了减法：

| 需求 | 实现 |
| --- | --- |
| 传参池可见 | 可见 Power **`传参池`**（`AlphaCorePower`），状态栏数字 = 池中传参**条数**，悬浮**只逐条列出池中内容**（v0.4：不再复述词条解释，卡面关键词已有） |
| 协议层数可见 | 可见 Power **`协议`**（`ProtocolPower`），状态栏数字 = 当前**层数**，悬浮显示「当前{N}层，结算时生成{档位协议}」+ 一句档位说明（v0.9：补回**实时层数 + 当前档位对应的协议牌**；档位 1-4→α，5-12→β，13+→γ，超出转活力） |
| 卡面词条 | 4 个自定义关键词（传参 / 响应 / 协议 / 迭代）自动挂在卡面，悬浮有完整说明。**传参 / 协议 / 迭代**用 `AutoKeywordPosition.None`（不自动追加到描述文本），卡面只保留手写的「传参：效果」行；**响应**用 `After`（自动追加标签） |
| 迭代计数器 | 迭代牌卡面显示 `迭代1（已打出 N 次）`，N 一直显示；成长后的数值实时反映在卡面数字上 |
| 响应牌增幅预览 | 响应牌卡面显示**传参池增幅后**的最终伤害 / 格挡（`AlphaDamageVar` / `AlphaBlockVar` 取 `AlphaCard.RawDamage` / `RawBlock`，再走引擎钩子）：例如池里有 α协议（+50%）时，阿尔法突袭卡面直接显示放大后的数字 |
| 已保留传参 | 完全响应卡面用 `{Retained}` 注入「本场战斗已保留的传参」列表；v0.6 起**按（种类 / 数值 / 子类型）聚合计数**，例：`抽1张牌 ×3、回复5点生命 ×2`（`AlphaCard.RetainedText` + `AlphaCorePower.GetRetained`） |
| 遗物计数 | 起始遗物「自我升级」的计数条显示**当前响应/迭代进度**（0 / 1 / 2，原版计数条样式） |

- 两个 Power 都**不走 `Amount`**（`Amount` 掉到 0 会被引擎移除，图标就消失了），
  层数/条数放在内部数据里，靠 `DisplayAmount` + `InvokeDisplayAmountChanged()` 驱动显示。
- 两个 Power 由起始遗物在**每个己方回合开始时**兜底挂上（`HasPower` 守卫，不会重复挂）。
- 关键词本地化在 `assets/localization/{zhs,eng}/card_keywords.json`，
  key = 命名空间根 + `-` + 字段名大写（`MyCharMod.Mechanics` → `MYCHARMOD-RESPONSE`）。
  本体已有 `card_keywords` 表，mod 的同名文件会被自动合并，**不需要**手动注册表。

## 3. 传参效果库（设计新卡时从这里挑）

这是「传参」能承载的效果全集，**可以自由组合**。写卡时 `BuildParam()` 返回一条 `ParamEntry`。

| 种类 `ParamKind` | 参数 | 效果 | 现有用例 |
| --- | --- | --- | --- |
| `Draw` | `Value` = 张数 | 抽 N 张牌 | 参数激活（抽1）、参数采集 |
| `Heal` | `Value` = 点数 | 回复 N 点生命 | β协议（回5） |
| `Replay` | `Value` = 次数 | **响应牌**重放 +N（区分「本牌」与「响应牌」） | γ协议（响应牌重放1→升级2） |
| `EffectBoost` | `Value` = 系数 | **响应牌自身**的伤害 / 格挡数值 ×(1+Value)（0.5 = +50%），不影响其他传参 | α协议（+50%→升级100%） |
| `DamageBoost` | `Value` = 系数 | **响应牌自身**的**伤害**数值 ×(1+Value)（1 = 双倍），不动格挡 | 凝神聚气（+100%） |
| `DamageAdd` | `Value` = 点数 | **响应牌自身**伤害 +N（平伤，不吃增幅） | 超频协议（+6→升级+9） |
| `GainProtocol` | `Value` = 层数 | 响应牌结算时获得 N 层协议 | 协议响应 |
| `Debuff` | `Value` = 层数，`Variant` = `DebuffKind` | 给**这张牌的本次目标**叠负面状态 | 待设计（B 级） |
| `Keyword` | `Variant` = `(int)CardKeyword` | 给**这张牌**永久加一个原版关键词 | 待设计（B 级） |
| `GenerateCard` | `Value` = 张数，`Variant` = `GenCardKind` | 生成 N 张牌加入手牌 | 小刀塑形（附魔小刀）、无限创想（随机无色牌） |
| `KeywordAllHand` | `Variant` = `(int)CardKeyword` | 给**手牌中所有**牌加一个原版关键词 | 虚实结合（手牌全加虚无） |
| `ChooseClassCard` | — | 从 3 张本职业随机牌中**选 1** 张加入手牌 | 预支未来 |

> 增幅类传参（`EffectBoost` / `DamageBoost`）在结算时**先累加成一个系数**，再统一乘到
> `（基础值 + 迭代加成）` 上并向下取整——所以 α 的 +50% 作用在**迭代成长之后**的数值上。
> 卡面预览同样会把这个系数算进去（见 §2）。

### 3.1 负面状态 `DebuffKind`

`Vulnerable`（易伤）/ `Weak`（虚弱）/ `Frail`（脆弱）/ `Poison`（中毒）。

> ⚠️ **设计约束**：负面状态作用于「这张响应牌的本次目标」。
> 所以带这类传参的**响应牌必须是指向敌人的牌**（`TargetType.AnyEnemy` / `AllEnemies`）；
> 做成自身指向型（`Self`）的牌，这条传参会**落空**（代码里直接 return）。

### 3.2 加关键词 `Keyword`

可选：`Exhaust`（消耗）/ `Ethereal`（虚无）/ `Innate`（固有）/ `Retain`（保留）/
`Unplayable`（不能打出）/ `Eternal`（永恒）。

> 语义是「本牌获得」。注意 `Ethereal`（虚无）在**打出之后**加是没意义的，
> 一般用在「生成牌」或「本牌打出前」的场景；`Retain`（保留）同理。
> 组合示例：`传参：本牌获得消耗` → 打出一张「打完就没」的爆发牌。

### 3.3 生成牌 `GenCardKind`

`ProtocolAlpha` / `ProtocolBeta` / `ProtocolGamma`（再造一张协议牌）/
`CopyThisCard`（复制本牌）/ `Shiv`（小刀，用本体 `Shiv.CreateInHand`）/
`EnchantedShiv`（随机合法附魔的小刀，`AlphaCard.GenerateEnchantedShivs`）/
`ColorlessRandom`（随机无色牌，`ColorlessCardPool`）。

## 4. 卡牌数值表（现状）

### 4.1 起始

| 牌 | 费 | 类型 | 效果 | 升级 |
| --- | --- | --- | --- | --- |
| 阿尔法突袭 | 1 | 攻击 | 随机造成 2 点伤害 3 次。**响应**。**迭代1：本牌伤害+1**（卡面显示已打出次数） | 伤害 2 → 3 |
| 参数激活（点火牌） | 1 | 技能 | 获得 7 格挡。**传参**：抽一张牌。**非响应** | 格挡 7 → 9，并获得**固有** |

- 随机 3 次 → 单体时是 6 点，群怪时分散。
- 阿尔法突袭现在是**纯响应牌**：池空时**也能打出**（吃不到加成），起手没抽到「参数激活」也不卡手；
  攒池再打收益更高（v0.5 解除硬门禁，见 [08](./08-卡牌清单.md) §11）。
- 参数激活基础版不带「固有」，第一回合不保证上手，靠 4 打击 / 4 防御过渡；升级后才变固有。

### 4.2 起始遗物 · 自我升级 / 自我进化

战斗内每完成 **3 次**响应或迭代，获得 **1 层协议**。

- 计数 = 响应触发次数 + 迭代结算次数之和。
- 遗物计数条显示**当前进度**（0 / 1 / 2，原版计数条样式）。
- 每满 3 次发 1 层协议（`AlphaCorePower.BumpResponseOrIteration` → `ProtocolPower.AddProtocol(1)`）。
- 经**欧洛巴斯之触**升级为古老版「自我进化」（`MyCharStarterRelicAncient`，`RelicRarity.Ancient`），
  每次里程碑给 **2 层**协议；替换由 `MyCharStarterRelic.GetUpgradeReplacement()` 完成。

| 继承迭代 | 1 | 技能 | 获得 5 格挡。**响应**（不消耗传参池）。**迭代1：格挡+1**（卡面显示已打出次数） | 格挡 +2 | 你的设计 |

> ✅ **v1.3 已删除**先古占位牌「阿尔法协议」（其依赖的「全局基础数值」机制早已移除，无重设计需求）。
> **v1.3 新增 / 改造的 A 级牌**（小刀塑形 / 零基启动 / 龙吼模块 / 紧急护壁 / 双重验证 / 全协议广播 / 歼灭龙息 / 存储预留 / 无限创想 / 预支未来 / 虚实结合）逐卡见 [08](./08-卡牌清单.md) §10.1。

> **完全响应 vs 继承迭代**：
> - 完全响应：吃一次，**加成永久挂在这张牌上**，之后每次打出都重放（哪怕池空）。
> - 继承迭代：**不消费池**，每次都能吃到池里的加成，但池留给别的响应牌用。

## 5. 循环示意

```
        回合开始
            │
   ① 消费全部协议层数 → 按档位发一张协议牌
   ② 挂上 / 刷新 传参池、协议 两个状态图标
            │
       打出「传参牌」（如 参数激活 / 协议牌）
            │
       传参入池 ──────────────┐
            │                 │
       打出「响应牌」          │
            │                 │
   消费整池 → 效果作用在本次结算 ┘
            │
       迭代计数 +1（本场战斗永久成长）
            │
     每满 3 次响应/迭代 → 升级一张手牌
            │
        （回到回合开始）
```

## 7. 已知问题 / 待办

### 7.1 待实测确认

1. **阿尔法突袭起手卡手**：已解决（v0.5）——响应牌池空时也能打出，只是没有加成，不再卡手。
2. **协议牌强度**：α/β/γ 都是 0 费且净赚能量，可能超模。保留现状，实测后调。
3. **协议档位跨度**：γ 要单回合攒 13 层，偏难。已补 4 张协议来源牌，实测看是否够。
4. **迭代卡面实时性**：伤害 / 格挡走 `AlphaDamageVar` / `AlphaBlockVar`、自定义变量走 `AlphaPreviewPatch`，
   都只改 `PreviewValue`（纯显示值），每次卡面刷新重算，不污染真实结算；需要实测确认「打完后重新抽到，卡面数字已 +1」。
5. **响应 / 迭代同时触发时遗物计两次**：像阿尔法突袭这种「既是响应又是迭代」的牌，
   一次打出会各计 1 次（共 2 次）。若手感偏快，可改成「每次打出只计 1 次」。
6. **伤害口径（B2，已修）**：预览与实战同经 `Hook.ModifyDamage` / `ModifyBlock`，
   需实测确认「有力量 / 活力时卡面数字 == 实际伤害，α 增幅按原始值计算」。

**设计新卡时的三个决策点**：
1. 它是**传参源**、**响应牌**、还是**两者都有**？（两者都有 = 自续，注意强度）
2. 响应牌吃到的传参要**落在哪**？（自身数值 / 敌人负面状态 / 本牌关键词 / 生成牌）
3. 要不要**迭代**？迭代值多少？（本场战斗永久成长，是滚雪球的主要来源）
