## 0. 规则补充（本轮定稿）

| # | 规则 | 说明 |
| --- | --- | --- |
| P1 | **传参默认作用于响应牌** | 除非条目声明「本牌」，否则传参一律作用在**响应牌本次结算**上。**但卡面描述一律直接写「响应牌…」**，不写含糊的「造成伤害」，避免误解。例：攻守兼备 → 「传参：响应牌造成伤害时获得等量格挡」 |
| P2 | **协议溢出转活力** | 协议档位 `0 / 1-4 / 5-12 / 13+` 对应 `无 / α / β / γ`；协议层数**超过 13 的部分**（`>13`），转化为等量**活力**（`VigorPower`，下次攻击加伤）。 |
| P3 | **先古牌允许跨战斗** | 先古牌可持久化到「本局游戏」（如阿尔法锚点）。先古难拿 + 需运转 + 需兼顾传参，成长曲线自己会兜住。 |
| P4 | **调节的「每回合第一次」** | 指**本回合第一次打出迭代牌**（所有迭代牌**共用**这一次），不是每张迭代牌各一次。 |
| P5 | **过载状态不做自伤保护** | 原汁原味，原版同类牌也会自伤致死。 |
| P6 | **完全形态的无限组合接受** | 需同时满足「拿到完全形态 + 拿到完全响应 + 传参能回手」，先古本就难遇，让玩家爽。 |
| P7 | **迭代不得新增传参** | 迭代只能**提升传参数值**（`传参：恢复1生命；迭代1：传参的恢复生命值+1`），**禁止**「迭代1：传参：效果」。能力牌触发器（如迭代广播，达到条件才塞一条传参）例外。 |
| P8 | **迭代三类效果** | 数值型（叠层）/ 次数型（叠词「一次」→ 叠次）/ 获得型（达到档位后**每次打出**按层数结算）。层数 = 已打出次数 ÷ X，**计数打出后才 +1**（本次用打出前层数）。详见 §17.1。 |

## 17. 本轮实测反馈的处理（v1.7 · 2026-10-04）

> 第九轮反馈（3 项：迭代口径统一 / 多多益善迭代 / 传参池合并显示）。代码已落地并部署（0 error / 0 warning）。

### 17.1 迭代效果统一口径（本轮定稿）

**层数公式**：`层数 = 已打出次数 ÷ 迭代间隔 X`。**计数器初始为 0，打出之后才 +1** —— 所以本次打出结算时用的是**打出前**的层数（「下次起生效」）。

| 类型 | 卡面写法 | 计数器 1 / 2 的表现 |
| --- | --- | --- |
| **数值型（叠层）** | `迭代1：给予1层易伤` | 给予 **1 层**易伤一次 → 给予 **2 层**易伤一次（层数累加进同一次施加） |
| **次数型（叠次）** | `迭代1：给予1层易伤一次` | 给予一次 1 层易伤 → 给予**两次** 1 层易伤（分开独立施加） |
| **获得型（叠层·每次打出）** | `迭代2：获得1点能量` | 达到档位后**每次打出**按层数给：1×层数 |

- 数值型：`获得3格挡` → 计数器2 = 6格挡；次数型：`获得3格挡一次` → 计数器2 = 3格挡两次。
- 获得型是**持续本场战斗**的牌面效果：达到档位后每次打出都结算（不是只在达档那一次）。
- 现有数值卡（阿尔法突袭 / 正击 / 递归练习 / 继承迭代 / 协议迭代 / 双重验证）保持「下次起生效」口径不变。

### 17.2 迭代 + 传参组合规则（本轮定稿）

- **禁止「迭代1：传参：效果」**（迭代时新增传参条目）——避免一次打出塞入大量词条、状态栏爆炸与潜在 bug。
- 迭代要作用于传参时，只能**提升该传参的数值**：例 `传参：恢复1生命；迭代1：传参的恢复生命值+1`。
- **例外**：能力牌走**触发器**（达到条件才塞一条传参，如迭代广播）——条数受触发次数约束，可控，与「迭代1：传参」不同，保持现状。

### 17.3 逐项处理
