## 2. 本轮落地

### 2.1 流水线 / 无限注入：固有改「升级后获得」

- **现象**：基础版起手必上手，升级收益（固有）形同虚设。
- **根因**：v1.10 第十六轮改这两张牌时（08 §26.4），只加了
  `protected override void OnUpgrade() => AddKeyword(CardKeyword.Innate);`，
  **没有删掉**原来的 `protected override IEnumerable<CardKeyword> BaseKeywords => new[] { CardKeyword.Innate };`
  → `CanonicalKeywords` 仍无条件产出 `Innate`，所以「未升级也有固有」。
- **修法**：删除两个类的 `BaseKeywords` 覆写（`AlphaCard` 基类默认 `Array.Empty<CardKeyword>()`），
  保留 `OnUpgrade()` 里的 `AddKeyword`。与 **冷息**（08 §29.0）完全同款。

```csharp
// 修后：基础无固有，升级才有（CanonicalKeywords 会拿到空 BaseKeywords）
protected override void OnUpgrade() => AddKeyword(CardKeyword.Innate);
```

- ★ **规则固化**：「升级后才出现的原版关键词」必须 = ① **不写** `BaseKeywords`（或删掉覆写）
  + ② `OnUpgrade()` 里 `AddKeyword(...)`。只做 ② 会退化成「本来就自带」；
  只做 ① 则升级也不给。原因：`CardModel.LocalKeywords` 会在升级前把关键词集合缓存死
  （`BaseKeywords => IsUpgraded ? ... : ...` 这种写法升级后不刷新）。

### 2.2 多层网络输出：单命令多段

- 见 08 §30.2（含 `VigorPower` / `ModifyAttackHitCount` 的可观测差异分析）。
- 一句话：原来 `for` 循环发的 X 次 `DamageCmd.Attack` 是 **X 个独立攻击事件**；
  改成一次 `Attack(...).WithHitCount(X)` 后，整次只算**一次攻击**、打 X 段 —— 与本体**旋风斩**、
  以及本 mod 的**阿尔法突袭 / 阿尔法锚点 / 协议提取 / 协议结算**同口径。
- `if (times > 0)` 守卫不能省：X=0 时发空命令会白走 `BeforeAttack`/`AfterAttack`（把活力扣掉）。

## 3. Q · 为什么要和旋风斩对齐（回复用户第 2 条）

**问**：多层网络输出为什么是一段一次结算，和旋风斩不一样？

**答**：因为两张牌走的不是同一条路：

| | 旋风斩 `Whirlwind`（本体） | 多层网络输出（改前） |
| --- | --- | --- |
| 实现 | `DamageCmd.Attack(dmg).WithHitCount(X)...Execute()` —— **1 条命令打 X 段** | `for (i < X) await DamageCmd.Attack(...).Execute()` —— **X 条独立命令** |
| 触发 `BeforeAttack`/`AfterAttack` | 1 次 | X 次 |
| 活力 `VigorPower`（「下一次攻击 +N 伤」） | `BeforeAttack` 记下、`AfterAttack` 才扣 → **每段都吃满** | 第 1 段吃完就归零 → **只有第 1 段吃到** |
| `Hook.ModifyAttackHitCount`（命中次数修正） | 生效 | **不生效** |

改后两者一致。**已改**（08 §30.2）。

## 4. Q · 模组内部 id 要不要一起改（待用户确认）

现状：**能看见的地方都已经改成「阿尔法」**，但内部标识仍是 `MyChar`：

| 层 | 现值 | 改成 AlphaMachine 的代价 |
| --- | --- | --- |
| manifest `id` / `pck_name` / 文件名 | `MyChar` | pck 内资源前缀 `res://MyChar/...` 要同步改，否则游戏内**所有资源为空** |
| assembly / dll / pck 名 | `MyChar.dll` / `.pck` | `tools/build.ps1` 的 `$modId`、csproj 的 `AssemblyName` |
| 命名空间 / 类名 | `MyCharMod` / `MyChar` / `MyCharAssets` / `MyChar*Pool` / `MyCharRelic*` / `MyCharStrike` / `MyCharDefend` | 161 个文件、614 处；**角色 id 由类名推得**（`character.MY_CHAR`）→ **旧存档里该角色的进度会失效** |
| 部署目录 | 游戏 `mods/MyChar/` | 改名后旧的 `mods/MyChar` 要手删，否则新旧两份并存 |
| Harmony id | `"MyCharMod"` | **无影响**（只是标签字符串；补丁目标都是游戏自己的类型，不随我们改名而失效） |
| 场景内资源引用 | 5 个 `.tscn` 里的 `res://MyChar/...` | 与 pck 前缀必须同时改 |
| 卡牌 ModelId / loc key | 由类名推得（`card.MY_CHAR_STRIKE` 等） | 改卡类名 → 卡 id 变 → 旧存档卡引用失效（显示名是中文，玩家看不见） |

→ **默认建议保持现状**（对外已是「阿尔法」，零风险）；如需彻底改名，建议只改「对外标识 + 角色类名」这一层。
