## 1. B 组 · 必须修的 Bug

### B1. 选牌不生效：`调用` / `数据收集` ⭐ ✅ 已修（v0.6）
- **现象**：`调用`（从抽牌堆选牌）与 `数据收集`（从弃牌堆选牌）点选后不生效。
- **根因（实锤）**：两张牌缺 `selectionScreenPrompt` 本地化键。`CardModel.SelectionScreenPrompt` 里
  `locString.Exists()` 为 false 时**直接抛异常**，`PlayEffect` 整个中断，所以「点了没反应」。
  游戏日志：`System.InvalidOperationException: No selection screen prompt for CARD.MYCHARMOD-CALL / -DATA_COLLECTION`。
- **已修**：给两张牌补上 `("selectionScreenPrompt", "选择 {Amount} 张牌…")` 词条（`Call.cs` / `DataCollection.cs`）。
- **排除的误判**：`CardSelectCmd.FromCombatPile` 真实重载只有
  `(ctx, pile, player, prefs)` 与 `(ctx, pile, player, prefs, filter)` 两种，**没有 `source` 参数**；
  现有调用与本体 `Dredge` / `Headbutt` 完全一致，无需改动。
- **验收**：两张牌都能弹出选择界面；选中的牌确实进入手牌 / 抽牌堆顶。← 待重启游戏实测确认

### B2. 伤害显示与实际不符（最高优先，可能牵连所有攻击牌）⭐⭐ ✅ 已修（v0.5）
- **现象**：卡面显示伤害很高（**已含力量 + 活力**），实际打出的很低。
  典型：`完全响应` 卡面显示 **60+**，实际只打 **10+**。
- **根因**：卡面预览走 `DamageVar.UpdateCardPreview` → `Hook.ModifyDamage(...)`（含力量/活力），
  再被 `AlphaPreviewPatch` 乘 α 增幅（二次放大）；实际结算走 `AlphaCard.ResolveValue` → `DamageCmd.Attack(floor(基础值 × 增幅))`，
  力量/活力由引擎在 `DamageCmd` 内部再加——两条口径不一致。
- **已修**：改用 `AlphaDamageVar` / `AlphaBlockVar`，`UpdateCardPreview` 里取 `AlphaCard.RawDamage` / `RawBlock`
  （= floor((基础值 + 迭代成长) × 增幅)），再走 `Hook.ModifyDamage` / `Hook.ModifyBlock`，与实战完全同路；
  `AlphaPreviewPatch` 不再碰伤害 / 格挡，只补自定义迭代变量。18 张攻击 / 格挡牌改用新变量。
- **验收**：无力量/活力时卡面数字 == 实际伤害；有力量/活力时两者也一致；α 增幅按原始值计算。← 待实测确认

### B3. 协议状态栏 tooltip 简化 ✅ 已修（v0.6）
- **现象**：悬浮里复述 α/β/γ 档位规则，啰嗦。
- **目标**：状态栏只显示**当前协议层数**（数字已有）；tooltip 精简（协议牌自带介绍，不必复述）。
- **已修**：`ProtocolPower.Localization["description"]` 改为
  `「回合开始时消耗全部层数，按档位将一张协议牌加入手牌。」`，删去档位表。

### B4. 完全响应「已保留传参」按类聚合 ✅ 已修（v0.6）
- **现象**：保留条目一多就是一长串，看不清。
- **目标**：同类聚合计数，例：`抽 1 张牌 ×3、回复 5 生命 ×2`。
- **已修**：`AlphaCard.RetainedText()` 用 `GroupBy((Kind, Value, Variant))` 分组，
  组内 >1 条时追加 `×N`；单条仍直接输出 `Describe()`。
