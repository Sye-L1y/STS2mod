## 1. 迭代效果的动态显示（需求 1）

**现状**：只有"数值变量"（伤害 / 格挡 / 协议）会随层数变；其余迭代效果是固定文字 + `（已打出{IterCount}次）`。
传参池 `PoolText` 把同类合并成 `×N`，**数值型与次数型看起来一样**。

**目标**（按 §17.1 口径解析成实际文案）：

| 类型 | 声明写法 | 层数 = 2 时的显示 |
| --- | --- | --- |
| 数值型（叠层） | 给予1层易伤 | 给予 **2层**易伤一次 |
| 次数型（叠次） | 给予1层易伤一次 | 给予1层易伤 **2次**（阿拉伯数字） |
| 获得型 | 迭代2：打出后获得1点能量 | 打出后获得 **2点能量**（直接显示总数） |

**方案**：给 `AlphaCard` 增加「迭代效果描述器」：
- 声明迭代类型（数值型 / 次数型 / 获得型）+ 一个"随层数解析"的模板或回调；
- 在 `AddExtraArgsToDescription` 注入 `{IterEffect}`，卡面写 `[gold]迭代[/gold]{IterEvery}：{IterEffect}`；
- 复用 `AlphaPreviewPatch` 思路，保证预览与实战同口径。

> Q1 已裁决：卡面必须动态；传参池的 `×N` 保持合并（区分需给每条传参带语义标记，成本较高）。

> **进度（2026-10-04）**：**批次 B 已落地并部署**（0 error / 0 warning）。
> `AlphaCard` 新增 `IterationEffectKind`（None / Numeric / Count / Gain）+ `IterationEffectSpec(Prefix, Value, Unit)`，
> 在 `AddExtraArgsToDescription` 注入 `{IterEffect}`（随层数解析）。
> 已回填：**双重验证**（次数型 → 层数 2 =「给予1层易伤2次」）、**逐步加载**（获得型 →「获得2点能量」+「已打出{IterCount}次」）、**多多益善**（获得型 →「获得4金币」）。
> 数值型（伤害 / 格挡 / 协议）继续由既有动态变量承担，无需 `{IterEffect}`。
>
> **修订（2026-10-05）**：按反馈统一显示口径——次数型用**阿拉伯数字**；获得型直接显示**总数**（value × 层数），移除 `{IterScale}`「（按层数结算）」提示与中文数字工具。

## 8. 风险与备注

- **复制类循环**：镜像构建 / 再声明 / 协议核心都可能与响应形成回手循环，参考 P6——先古级才允许无限，这几张是稀有，需设**消耗 / 每回合一次 / 数值上限**兜底（逐张实测）。
- **新增钩子**：厄难覆盖需要"协议消耗"事件；终响激发需要"传参入池"事件；目标回馈需要"伤害结果（未被格挡值）"。这三处是本轮最大的框架扩展点。
- **动态费用**：优美公式需运行时改费用，注意与既有 `SetToFreeThisTurn`（E5）区分。
- **迭代效果显示**：`{IterEffect}` 是运行时状态（随层数变），要保证预览走 `PreviewValue` 且与实战同口径，避免重蹈 B2"卡面 60、实打 10"。
- **群伤传参与活力抢结算**（已修）：响应牌打出时，池里的「群伤」传参（`ParamKind.DamageAll`，来自「参数采集」）原本在响应阶段**先于本牌自身攻击**结算。它是一次由本牌发起的强化攻击，会把玩家的**活力**（`VigorPower` 只认「下一次攻击」，命中后即清空）消耗掉；于是本牌自身攻击吃不到卡面预览里已算进去的活力，表现为**卡面 29、本牌实打 25**（差额 = 活力层数）。修法：`AlphaCard.OnPlay` 把 `DamageAll` 传参**延后到本牌自身效果之后再结算**，活力留给本牌攻击（群伤仍照常吃力量）。适用于所有带响应的攻击牌。
- **部署提醒**：改完必须**重新编译 + 部署**，否则验收看到旧行为（历史多次踩坑）。
